Документ‑контекст для отдельной ветки работ по товарным матрицам. Здесь собрано всё, что нужно знать о проекте, чтобы продолжать его без доступа к переписке: назначение, устройство, данные, логика каждого модуля, правила работы с заказчиком, текущее состояние и открытые задачи. ## 1. Что это и для кого

**M22 Product Radar** — система рыночной разведки для компании M22 (сайты m22.ru и radiosync.ru; бренды Radiosync и Kromix). Заказчик — Евгений Васильев (M22), нетехнический пользователь: всё должно открываться в браузере, объясняться русским языком и работать «одной кнопкой».

Система:

1. **Собирает** товары и цены M22 с двух сайтов и товары/цены конкурентов с их сайтов, маркетплейсов, ЕИС (госзакупки) и данных о спросе.
2. **Нормализует** всё в единую структуру: категория, тип изделия, ключ модели, вместимость комплекта, цена за единицу, технические характеристики (дальность, каналы, диапазон, экран, автономность, вес).
3. **Сопоставляет** товары конкурентов с товарной матрицей M22 (точная модель / прямой аналог / функциональный / комплект / аксессуар / заменитель / смежный / новая категория) с уверенностью 0–1.
4. **Выдаёт сигналы** (15 типов: цена конкурента изменилась, товар появился/исчез, M22 дороже/дешевле рынка, одну модель продают несколько продавцов, категории нет у M22, расхождение между сайтами M22, спрос вырос и т. д.), **рекомендации** (конкретные действия с приоритетом, основанием, ответственным и сроком), **карточки гипотез** (Product Discovery) и **еженедельный отчёт** (PDF/XLSX/CSV).
5. **Ведёт реестр конкурентов** с уровнями A/B/C, ролями, сервисным профилем (гарантия, тест‑драйв, монтаж, склад, лизинг…), юрлицами и финансами из Rusprofile, а также **сравнительную таблицу «признаки × продавцы»** и **рекомендации, что добавить на сайты M22**.

Контур исследования — экскурсионная деятельность и связанные B2B‑решения: радиогиды, аудиогиды, синхронный перевод, одноразовые и многоразовые наушники, микрофоны, зарядные кейсы/док‑станции, готовые комплекты, аренда, рации, заменители (приложения).

**Стек:** Python 3.12 (`C:\Users\Adm\AppData\Local\Programs\Python\Python312\python.exe`), FastAPI + Jinja2 (серверный рендер, без внешних CDN), SQLite (WAL), APScheduler, requests + BeautifulSoup/lxml, openpyxl, reportlab, pytrends. Всегда `PYTHONUTF8=1`; скрипты из папки радара запускать с `PYTHONPATH=.`.

**Запуск:**

```bash
python -m radar init        # база + миграции + справочники
python -m radar collect all # сбор (m22, radiosync, competitors, suggest, trends)
python -m radar analyze     # сопоставление, сигналы, рекомендации, гипотезы
python -m radar report      # еженедельный отчёт
python -m radar serve       # веб: порт 8022
python -m radar pipeline    # всё подряд
```

В продуктиве сервер запускается скрыто: `cscript scripts/start_hidden.vbs` (ярлыки на рабочем столе «Запустить радар», «Остановить радар», «Обновить данные радара», «Открыть доступ к радару для коллег.bat»). Перезапуск после изменений в `app.py`: сначала остановить процессы `*radar serve*` (PowerShell), затем **отдельным вызовом** запустить vbs (совместный вызов в одной команде падает с кодом 255). Шаблоны Jinja перечитываются без перезапуска; версия и метка статики вычисляются при каждом запросе.

**Доступ:** `http://127.0.0.1:8022`, для коллег `http://SALES5:8022` (или по IP 192.168.150.x). Вход по общему паролю (RADAR_PASSWORD в `.env`, сейчас 2202), cookie `radar_auth` с HMAC‑подписью (RADAR_SECRET), сессия 30 дней. Публичные пути: `/login`, `/health`, `/static/`. **Нерешённая проблема:** AmneziaVPN на машине заказчика заворачивает 192.168.150.x в туннель, коллеги не подключаются; решение — отключить VPN или вынести на VPS (Dockerfile и docker‑compose есть, nginx‑пример в docs/DEPLOY.md).

**Конфигурация** — `.env` (см. `.env.example`): пути, порт, задержки HTTP, расписание (M22 05:00, конкуренты 06:00 ежедневно; спрос пн 07:30; отчёт + бэкап пн 08:30), пороги сигналов (изменение цены ≥3 %, разрыв с рынком ≥10 %, минимум 3 сопоставимых, изменение спроса ≥25 %, аномалия z ≥2.5).

**Данные:** `data/radar.sqlite3` (рабочая база), `data/raw/<источник>/<дата>/*.html` (сырые страницы), `data/backups`, `data/exports`, `data/logs`. Файл `data/radar.db` — пустой артефакт, не используется.

**Тесты:** `python -m pytest -q` (25 тестов; отдельная тестовая база, фикстуры сохранённых страниц).

## 3. Правила работы с заказчиком (обязательные)

- **Версия.** Файл `VERSION` (`X.Y.Z`) — единственный источник версии; показывается в сайдбаре и в `/health`. **Каждое сообщение заказчика = +1 к Z** без исключений, первым действием: `python scripts/bump_version.py`. При Z>99 скрипт делает Y+1, Z=0. X — только вручную по решению заказчика (`bump_version.py major`).
- **Журнал версий** `docs/ЖУРНАЛ_ВЕРСИЙ.md`: при каждом повышении версии запись `## X.Y.Z — дата` и пункты `- …` коротко, языком пользователя. Раздел «Журнал версий» в меню (`/changelog`) читает этот файл.
- **Последняя строка каждого ответа:** «Версия сейчас: X.Y.Z».
- Коммиты: `git -c user.name="M22 Radar" -c user.email="radar@m22.ru" commit -m "vX.Y.Z: …"`, трейлер `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Заказчик уже дважды жаловался, что версия «не обновляется» — проверять, что `/health` отдаёт новую версию после каждого изменения.
- Пустые значения в интерфейсе не «—», а словами: «нет данных», «не найдено на сайте», «не в наличии», «цена по запросу».
- Суммы денег — в удобной единице: «17 млрд ₽», «242 млн ₽», «327 тыс. ₽» (фильтр `rub` в app.py), не «21 030 млн».
- Все таблицы сортируются кликом по заголовку, границы колонок тянутся мышью; вёрстка на всю ширину; тёмная тема (переключатель, `?theme=dark`, должна читаться на всех страницах).
- Технические ограничения при патчах: Jinja‑ключи `values`/`items` конфликтуют с методами dict — использовать `vals`, `lines`; heredoc‑скрипты портят `\w \s \d` — патчи писать в файлы через Write.

## 6. Сбор данных (collectors)

Общий контракт: `run(conn) -> dict`, запись в `source_runs`, ошибки в `error_log`. HTTP через `radar/http.py`: проверка robots.txt, задержка ≥2 с на домен, повторы при 429/5xx, сохранение сырых страниц в `data/raw`.

### 6.1 m22.ru (`collectors/m22.py`)
`sitemap.xml` → URL из разделов контура (`IN_SCOPE_SECTIONS`: sistemi-radiogid, sinhronniy-perevod, gotovie-resheniya, odnorazovie-naushniki, komplektuyuschie-dlya-gidov, mikrofoni…, interkom-sistemi, racii-i-aksessuari, zaryadnie-ustroystva, garnituri) → страница товара: JSON‑LD Product (имя, цена, наличие, бренд, категория, описание, sku), fallback на CSS (`.product-page-desc-price`, `.product-page-desc-artikul`), характеристики из `<ul><li><strong>Группа</strong>…<span>Параметр</span><span>Значение</span>` → `specs_json` по группам, «Комплектация» → `kit_json`, варианты (`.product-mods-pos`) — отдельные страницы из sitemap, изображения. Товары, не встреченные при полном проходе (>10 страниц), помечаются `is_active=0`.

### 6.2 radiosync.ru (`collectors/radiosync.py`, Tilda)
`sitemap-store.xml` → `/tproduct/…` → `.js-store-prod-name`, `.js-store-prod-price-val[data-product-price-def]`, `lowPrice/highPrice`, `.js-store-prod-sku`, `.js-store-prod-charcs` («Характеристики»), offers по SKU → варианты как под‑товары с `parent_url` и url `#sku`. Раздел сайта по URL (`comparisontable` → Радиогиды, `accessories`, `11213123132` → Одноразовые наушники, root → Комплексные решения). Плюс страница `/rent` → один товар «Аренда…» с минимальной суммой и списком позиций, `category_slug=rental`.

### 6.3 Конкуренты (`collectors/competitor_generic.py`)
Универсальный парсер по `monitored_pages`:
- **product**: CSS‑конфиг → JSON‑LD Product/Offer (в т. ч. `@graph`, `itemListElement`) → microdata/OpenGraph (`itemprop=price`, `product:price:amount`, `data-product-price-def`) → эвристика «самый внутренний элемент с ценой в `main`, без шумовых слов (доставка, скидка, в месяц…)». Название: h1 → og:title → itemprop=name → title. Характеристики (`extract_specs`): JSON‑LD additionalProperty, таблицы th/td, dl/dt/dd, `li/p` вида «параметр: значение» с подсказками ключей. Картинка: og:image → itemprop=image → первый крупный img.
- **catalog/listing**: CSS‑конфиг → JSON‑LD ItemList → эвристика «карточка = предок элемента с ценой (до 7 уровней), содержащий ссылку и <700 символов»; имя карточки из заголовка/`[class*=title|name]`/самой длинной осмысленной ссылки/alt картинки. Позиции фильтруются `classify_category != None`. Для каталожных позиций дополнительно открываются страницы товаров того же домена (`_enrich_from_product_pages`, ≤40 за проход, не чаще раза в 7 дней) для характеристик, фото, описания, полного названия.
- **rent** (или URL с rent/arenda/prokat): `category_slug=rental`.
- **sitemap**: раскрытие карты сайта в страницы (см. 5.3).
- Позиция каталога, не встреченная ≥2 дней после успешных проверок, помечается неактивной. Ошибки robots → `robots_disallowed`.

`common.upsert_competitor_product`: чистит имя, классифицирует категорию, тип, вместимость, бренд (`detect_brand` по списку BRANDS), ключ модели; при совпадении url без совпадения имени (`match_by_url`) сохраняет более информативное имя; пишет историю цен при изменении. `common.renormalize` пересчитывает категорию/тип/вместимость/ключ для всех товаров без сети (варианты radiosync наследуют вместимость от m22 по артикулу).

### 6.4 Прочие источники
- **Wildberries** — публичный JSON поиска витрины по 6 запросам, 1 запрос / 20 с, цена в копейках, собственные листинги M22 исключаются; продавец «Wildberries — продавцы экскурсионного оборудования».

- **Google Trends** (pytrends) — seed‑запросы группами по 5, пауза 70 с, 429 → пауза; related queries расширяют семантику.

## 7. Нормализация (`normalize.py`, `specs.py`, `specs_extract.py`, `categories.py`)

### 7.1 Цена — `parse_price`
Регулярное выражение на «32 500 ₽», «32500,00», «32.500», «руб.», RUB; отсечка 0 < цена ≤ 1e8.

### 7.2 Ключ модели — `model_key(name, sku)`
Приоритетные шаблоны: `SGTR\d\d[A-Z]?`, `UG\d\d`, `AG\d\d\d`, затем известные префиксы (HDE, SR, EK, SK, TT, RS, RG, WT, EJ, MT, DR, X22, RT, BF, UV, CL, SWB, STDB, STRB, MC, CP, PW, MS, WS, LT, LR, DLT, DLR, ATS, FT, ES) + 2–5 цифр, затем одиночные буквы T/K/R/W/E + 3–5 цифр, затем любые 2–6 букв + цифры (исключая USB, AUX, LED, IP, MHz, GHz, VHF, UHF, FM, RF и предлоги), затем «бренд + слово» (REINVOX‑DUO, RETEKESS‑…), затем артикул с буквами. Используется для точного совпадения и для сигнала «одна модель у нескольких продавцов» (там код без бренда считается различимым только если ≥2 букв в префиксе и ≥4 знаков: RG18, WT300R — да; T100 — нет).

### 7.3 Категория — `classify_category(name, description, site_path)`
1) По началу названия: «…наушник…» → одноразовые/многоразовые; `HEAD_RULES` (радиогид/tour guide/шептал → radiogid; «система синхронного» → sync_translation; аудиогид; аренда; комплексное решение; усилитель голоса).
2) Затем `CATEGORY_RULES` по ключевым словам названия, потом раздела сайта, потом описания, в порядке: sync_translation, audiogid, disposable_headphones, reusable_headphones, charging_cases, voice_amplifier, microphones_guide, rental, kits_solutions, intercom_events, radio_walkie, adjacent_new, radiogid (последний — самые общие слова: передатчик, приёмник, receiver…).
Категории (17): radiogid, audiogid, sync_translation, disposable_headphones, reusable_headphones, microphones_guide, charging_cases, kits_solutions, rental, industrial_tours, museum_equipment, conference_delegations, intercom_events, voice_amplifier, radio_walkie, substitutes_apps, adjacent_new. Названия — `CATEGORY_NAMES`.

### 7.4 Тип изделия — `detect_kind(name)`
kit (комплексное/готовое решение, Прайм, Профи) → system (начинается с «радиогид система», «система синхронного», «комплект для…») → rental → transmitter/receiver (по началу «передатчик/приёмник» до « для »; если оба слова или «система/комплект» + одно из них → system) → case_charger (кейс, докстанция, сумка, зарядн…) → headphones / accessory (чехлы, накладки, амбушюры) → microphone (микрофон, гарнитура, headset) → audioguide → accessory (триггер) → system (система, комплект, kit, set) → other.

### 7.5 Вместимость — `detect_capacity(name)`
Только из названия («на 25 персон», «для 10 человек», «до 60 устройств», «32 слота», «1+25», «5 шт»). Описание намеренно игнорируется (перечисляет все варианты).

### 7.6 Контур — `is_in_scope`
Товар без категории — вне контура (кроме `radio_walkie`); исключаются маркеры (soundpeats, игровая гарнитура, пусковое, тент, батарейка, автомобильн, кальян, медицинск, пейджер…).

### 7.7 Характеристики — `specs.normalize(name, description, specs_json, price, capacity)`
Плоский текст = название + «параметр: значение» + описание. Поля матрицы:
- `range_m` — «дальность/радиус/range … N м» (20…3000), fallback «150 м» в названии;
- `channels` — «N канал/channel/ch» (1 < N ≤ 20000);
- `battery_h` — по «приёмник … N ч», «аккумулятор/автономность/время работы … N ч», «до N ч» (1…200);
- `freq_band` — 2.4 ГГц (2.4, 2.4—2.483 ГГц, 2400–2483 МГц) / UHF (uhf, 4xx–9xx МГц) / VHF / FM / ИК;
- `weight_g` — «вес/масса N г» (10…500);
- `capacity` — из аргумента или названия;
- `two_way` — двусторонняя/обратная связь/full duplex;
- `display` — по параметру «экран/дисплей» (значение «нет/без/no» → False) или по словам display/lcd/oled в тексте;
- `charging_case` — кейс/докстанция/charging case.
`BETTER_HIGH` = range, channels, battery, capacity; `BETTER_LOW` = price, weight. `justify(offers, m22_candidates, category_in_m22)` — обоснование «стоит ли выводить аналог»: новая группа для M22; минимальная цена ниже M22 ≥25 %; характеристика лучше на ≥30 % (дальность, каналы, автономность), вес ≤70 %, двусторонняя связь, цифровой 2.4 ГГц при аналоговых у M22 → вердикт.

### 7.8 Извлечение характеристик со страниц — `specs_extract.py`
Для сайтов, где `extract_specs` из парсера ничего не дал (Tilda‑лендинги, проза): текст страницы построчно; `LABELS` (Дальность, Каналов, Диапазон частот, Экран, Работа от аккумулятора, Вес, Аккумулятор, Время зарядки, Разъём зарядки, Память) — значение в той же строке или на следующей; секции комплекта («Приёмник», «Передатчик») дают префикс ключа «Приёмник · Вес»; `PROSE`‑шаблоны («работает до 150 часов», «до 150 метров», «весит 40 грамм», «более 5000 каналов», «2.4—2.483 ГГц»). `enrich_competitor(conn, competitor_id)` дозагружает страницы и сливает найденное в `specs_json`. Выполнено для CrystalSound (81 из 85 позиций); для остальных A — в плане.

### 7.9 Цена за единицу — `categories.unit_price`
Наушники: цена упаковки / количество из названия («100 шт», «уп. по 50», «x100»); одноразовые дороже 500 ₽ без количества → цена за штуку неизвестна. Системы и комплекты: цена / вместимость (за одно место); без вместимости — несопоставимо. Остальное — как есть.

## 8. Сопоставление (`matching.py`)

`run_matching`: для каждого активного товара конкурента вычисляется `norm` (характеристики) и вызывается `match_one` (0–3 сопоставления):

1. Товары с брендом Radiosync/Kromix у конкурентов → `adjacent` 0.3 («перепродажа собственного бренда»).
2. Аренда → не сопоставляется.
3. **Точная модель**: совпадение `model_key` (≥4 знаков) → 0.85; +0.1 совпадает бренд / −0.25 бренд отличается; вместимость: +0.05 совпадает / −0.15 отличается (тогда тип `kit`, ≤0.55); если тип изделия отличается → `functional` ≤0.4; система с известной вместимостью у M22, но неизвестной у конкурента → ≤0.55.
4. Категории нет → без сопоставления; `substitutes_apps` → `substitute` 0.6; категория есть у конкурента, но не у M22 → `new_category` 0.7.
5. **Аналоги внутри категории и типа**: база 0.4 (system) / 0.5 (остальные); штрафы `feature_compat` (двусторонняя связь у одного и нет у другого −0.35/−0.25; разный класс диапазона аналог/цифра/ИК −0.2; дальность отличается >2× −0.1); вместимость (совпадает +0.25, близкая +0.1, отличается −0.15, неизвестна у конкурента‑системы −0.15); цена: для систем ±30 % +0.15, ≤2× +0.05, >2× −0.1; для приёмников/аксессуаров цена не критерий (+0.1, штраф только при >3×). Системы — адресно (лучшие 1–2, не хуже лучшего −0.15), остальные — все кандидаты ≥0.55 (до 8). Тип: `direct_analog` ≥0.6, иначе `functional`; для аксессуаров/наушников/микрофонов — `accessory` ≥0.55; kit при участии готового решения. Уверенность ограничена 0.8.
6. Категория есть у M22, но такого типа изделия нет → `adjacent` 0.5.

`needs_review = confidence < 0.7`; вручную подтверждённые/отклонённые (`review_status`) не перезаписываются. `comparables_for(m22_id, min_conf)` — сопоставимые с ценой (exact_model, direct_analog, RUB, не аренда, цена ≥10) для сравнения с рынком. Раздел «Сопоставления» (`/matches?review=0`) — ручная проверка.

## 9. Товарные матрицы в интерфейсе

### 9.1 Матрица M22 — `/matrix` (matrix.html), `/matrix/{id}` (product_detail.html)
Таблица всех товаров M22: товар (ссылка на карточку и на сайт), сайт, категория, модель/артикул, вместимость, цена (с зачёркнутой старой), наличие, число сопоставлений, сигналов, замеров, дата снятия. Фильтры: категория, сайт, контур (только в контуре / все собранные), поиск по названию/артикулу/модели. Сводка по категориям (число, мин–макс цена). Экспорт `/export/matrix.xlsx|csv`.
Карточка товара: характеристики по группам, комплектация, фото, история цен, «двойник» на другом сайте (по артикулу или модель+вместимость+тип), варианты, все сопоставления с конкурентами (тип, уверенность, причины), медиана сопоставимых цен, сигналы по товару, ссылка на сравнение `/compare?product=id`.

### 9.2 Матрица конкурентов — `/competitor-matrix` (competitor_matrix.py + competitor_matrix.html)
Три вида:
- **Товары** (`view=matrix`): все товары всех конкурентов: фото, продавец (группа), товар (ссылка; «(N стр.)» если та же позиция с той же ценой найдена на нескольких страницах сайта — `_collapse_duplicates` по продавцу + нормализованному имени + цене), категория, тип, модель, цена/наличие («цена по запросу», «наличие не указано»), цена за ед./место, колонки характеристик `MATRIX_COLS` (дальность, каналов, диапазон, экран, автономность, вес, двусторонняя связь, вместимость; пусто → «нет данных», False → «не указано»), аналог M22 (ссылка, цена, тип сопоставления, %), статус (в продаже / новый после базового замера / исчез), дата снятия и число замеров. Фильтры: продавец, категория, тип, статус (в продаже / исчезли / новые / без аналога у M22), поиск. Экспорт XLSX/CSV (`export_rows`, русские заголовки).
- **Покрытие категорий** (`view=coverage`): карта «продавец × категория» с числом товаров (в скобках — с ценой), строка M22 первая; красным — категории, где у M22 ничего нет, а у конкурентов есть (`gaps`).
- **Что появилось / исчезло** (`view=changes`): позиции с `first_seen_at` после `baseline_date` (2026‑09‑06), неактивные позиции, сигналы изменения цен за 30 дней.

### 9.3 Категории — `/categories`, `/categories/{slug}` (categories.py)
По каждой категории: товары M22 с ценой за единицу, предложения конкурентов (с сопоставлением), продавцы, **ценовое положение по типу изделия** (минимальная цена M22 vs предложения конкурентов того же типа: доля дешевле M22, минимум, медиана, разрыв в %, список более дешёвых), вердикт: `gap` (у M22 нет товаров), `no_data` (<3 предложений с ценой / аренда несопоставима), `attention` (≥50 % предложений дешевле M22), `watch` (≥20 %), `ok`. Также сигналы, рекомендации, гипотезы, тендеры по категории.

### 9.4 Сравнение — `/compare`
Колонки: товары M22 и предложения конкурентов (по сигналу, по товару M22 или по списку id): фото, цена, продавец, нормализованные характеристики (лучшее значение подсвечено), сырые характеристики (до 40 ключей), вердикт `justify`.

### 9.5 Реестр конкурентов и вкладки — `/competitors…` (profile.py)
Вкладки: **Реестр** (только продавцы с сайтами; уровень A/B/C, роль продавца — `seller_roles`: производитель/владелец бренда, реселлер: <бренды>, прямой продавец, аренда, продавцы на площадке, заменитель, участник госзакупок; число товаров, доля в наличии, сервисный профиль, ряд плашек расширенных признаков, строка УТП, строка юрлица; фильтры по категории и уровню; форма добавления) · **Показатели** (`dashboard_data`: юрлица объединены по ИНН; KPI, диаграммы выручки и госзакупок, сводная таблица: сотрудники, выручка и динамика, госзакупки и крупнейшие заказчики, арбитраж, исполнительные производства, налоги, финсостояние, товарные знаки, уверенность сопоставления; блок рекомендаций) · **Сравнительная таблица** (`comparison_table`: строки — признаки [гарантия, сервисный центр, подменный фонд, аренда, бесплатная доставка + 15 расширенных: тест‑драйв, монтаж, сопровождение мероприятий, склад, производство, брендирование, обучение, 44‑ФЗ, лизинг, шоурум, доставка по России, 24/7, лет на рынке, клиентов, многоязычные], колонки — M22 первой, затем конкуренты; зелёная ячейка — у конкурента есть, у M22 нет; при наведении фрагмент текста и ссылка на страницу‑доказательство; «нет данных» = не найдено на проверенных страницах) · **Участники тендеров** (`tender_participants`: сегменты «Крупный ИТ‑интегратор» (выручка ≥1 млрд), «Средний поставщик» (≥100 млн), «Малый поставщик», «ИП‑тендерщик», «В реестре недобросовестных», «Без данных о масштабе»; KPI, диаграмма сумм закупок, полная таблица, форма добавления по ИНН) · **Матрица товаров** · **Сопоставления**.
Карточка конкурента (`/competitors/{id}`): данные, товары, страницы мониторинга (добавить/включить/проверить), профиль с доказательствами и ручными правками, блок «Юрлицо и финансы» (форма `legal_form`), «Есть у этого конкурента, нет на сайтах M22» (`site_recommendations(only_competitor=id)`).

**Сервисный профиль** (`scan_competitor`): сохранённые страницы товаров конкурента (только того же домена — `_domain`) + типовые пути `GUESS_PATHS` (/, /delivery, /garantiya, /service, /about, /rent, /test-drive, /montazh, /tender, /lizing, /clients…), регулярные выражения `RX`/`EXTRA_RX` (уточнены после ложных срабатываний: выставочный зал ≠ шоурум, «монтаж видео» ≠ монтаж, «синхронный перевод» ≠ многоязычность, «производим дезинфекцию» ≠ производство), значения с фрагментом и URL; ручные значения (`_manual`, `*_manual`) поверх автоматических. Эталон M22 — `settings.m22_profile` (сканирование m22.ru + radiosync.ru; гарантия 2 года из характеристик) + `m22_profile_manual` (правится в Настройках).

**Рекомендации «Что добавить на m22.ru и radiosync.ru»** (`site_recommendations`): по каждому признаку — кто из конкурентов заявляет то, чего нет у M22, число таких конкурентов (рычаг), статус M22, конкретное действие для сайта (`SITE_ACTIONS`); особые пункты: «Госзакупки как канал» (если у конкурентов есть контракты) и уникальный «Подменный фонд» (никто не заявляет). Показывается на вкладках Показатели и Сравнительная таблица (шаблон `_site_recs.html`) и в карточке конкурента.

## 10. Аналитика: сигналы, рекомендации, гипотезы, обратная связь

### 10.1 Сигналы (`signals.run_all`)
Каждый сигнал: тип, важность (high/medium/low), вид факта (fact / inference / hypothesis), уверенность, что произошло, старое/новое значение, период, источник и ссылка, доказательства (JSON), почему важно, рекомендуемое действие, `dedupe_key` (защита от повторов), статус (new / in_research / accepted / rejected / done), комментарий, ответственный.
- `competitor_price_change` — два замера с `run_id` в разные дни после базовой даты, изменение ≥3 %, отношение ≤5× (иначе ошибка разбора); high при ≥15 % и наличии сопоставления.
- `product_appeared` / `new_kit_solution` / `product_disappeared` — относительно первого замера конкурента.
- `new_category` — категория у конкурента, которой нет у M22.
- `new_competitor` — добавлен после базовой даты.
- `multi_competitor_product` — одинаковый бренд + код модели у ≥2 независимых продавцов (группа = один продавец); обоснование через `justify` против ближайших моделей M22 того же типа; high при ≥3 продавцах и отсутствии у M22 и наличии причин; обновляется при повторном анализе.
- `m22_price_above_market` / `below_market` — ≥3 уникальных сопоставимых (конкурент+название) с уверенностью ≥0.6, медиана, разрыв ≥10 %; уверенность ≤ min(средняя+0.15, 0.45+0.05·n, 0.95); high при ≥20 %; дубли radiosync по артикулу m22 пропускаются.
- `demand_change`, `demand_anomaly` (z ≥2.5), `category_growth_existing` / `category_growth_gap` — по сериям Google Trends / Wordstat.
- `new_use_case` — сценарии применения (промышленные экскурсии, музеи, храмы, тихая дискотека…) в описаниях ≥2 конкурентов и не в текстах M22.
- `cross_site_discrepancy` — разные цены одного товара на m22.ru и radiosync.ru (по артикулу, иначе модель+вместимость+тип и похожесть названия ≥0.5) и позиции radiosync, которых нет на m22.ru.
- `source_error` — ≥2 сбоев источника или ≥3 сбоев страницы.
Сейчас в базе: multi_competitor 15, below_market 9, above_market 3, new_use_case 6, cross_site 2, source_error 25.

### 10.2 Рекомендации (`recommendations.generate`)
Сильная рекомендация только при сильном факте (≥3 сопоставимых, подтверждённая цена) или ≥2 согласующихся сигналах: ценовой разбор (P1 при ≥20 %), синхронизация цен между сайтами (P2), выравнивание ассортимента (P3), запрос модели у поставщиков при ≥3 продавцах и обосновании (P2), исследовать категорию у ≥2 конкурентов (P3), кампания по растущей категории (P2), сценарии применения в карточки (P2), реакция на снижение цены конкурента, восстановление источников (P3). Ответственные: Собственник, Продуктовая команда, Маркетинг, Продажи, Закупки. Статусы new/accepted/rejected/in_progress/done, комментарии.

### 10.3 Гипотезы (`discovery.generate`)
Карточки: новая категория (≥2 конкурентов), ввод модели (≥2 продавцов + обоснование), растущая категория без товаров M22, технологические заменители. В карточке: описание, как обнаружено, спрос, конкуренты, рыночные цены, связь с M22, сегмент, сценарий, за/против, риски, чего не хватает, следующий шаг, ответственный, статус решения. Сигнал можно «Отправить на исследование» → карточка.

### 10.4 Обратная связь (`feedback.py`)
Каждое решение человека (принять/отклонить сигнал, рекомендацию, гипотезу) пишется в `feedback` со снимком доказательств; доля подтверждений по типу (и типу+категории) после 3 проверок даёт множитель уверенности 0.6…1.15 для новых сигналов того же типа; подтверждённый ценовой сигнал закрепляет сопоставления (`confirmed`), отклонённый — отправляет их на проверку.

### 10.5 Отчёт (`reports.py`)
10 разделов: главные изменения, товары M22, цены конкурентов, новые товары, спрос, товарные пробелы, гипотезы, риски, решения собственника, действия на неделю + ограничения данных. Экспорт PDF (шрифт Arial/DejaVu), XLSX, CSV; сохраняется в `reports`; при генерации по расписанию делается бэкап.

## 11. Веб‑приложение (`radar/web/app.py`)

Маршруты: `/` (главная: пять ответов, главные сигналы, действия), `/actions`, `/signals`, `/competitors` (+ `/tenders`, `/dashboard`, `/compare`, `/profile-scan-all`, `/{cid}`, `/{cid}/update`, `/{cid}/pages/add`, `/{cid}/profile-scan`), `/pages/{pid}/toggle|check`, `/matches`, `/matches/{mid}/review`, `/competitor-matrix`, `/categories`, `/compare`, `/matrix`, `/matrix/{pid}`, `/demand` (+ `/add`), `/import` (Wordstat, Trends CSV, запросы, конкуренты, цены вручную), `/opportunities` (+ детали), `/sources` (статусы, журнал ошибок, планировщик, кнопки запуска, переключение источников), `/reports` (+ генерация, экспорт), `/export/{what}.{csv|xlsx}` и `/export/backup.sqlite3`, `/settings` (владельцы, категории, профиль M22), `/analyze`, `/changelog`, `/health`, `/login`, `/logout`.
Jinja‑фильтры: `money` (₽ с пробелами), `rub` (млрд/млн/тыс.), `pct`, `dt`, `uj`. `render()` добавляет `app_version`, `asset_version`, списки категорий/конкурентов. Статика: `app.js` (сортировка по клику — числа, цены с единицами, даты, текст, пустые в конец, строка УТП следует за основной; перетаскивание ширины колонок; тема в localStorage `radar_theme`), `style.css` (полная ширина, тёмная тема через `html[data-theme="dark"]`, плашки `.attr`, `.kpis`, `.grid2`, `.recs-card`).

Планировщик стартует вместе с сервером (`scheduler.start`), один сбор одновременно (`_lock`), повтор через 2 ч до 2 раз, запуск из интерфейса в фоне (`run_now`). Два конкурентных сбора дают «database is locked» — запускать последовательно.

## 13. Известные ограничения и открытые задачи

**Ограничения данных**
- Цены конкурентов сняты с 04.09.2026; сигналы изменения цен появляются только после замеров в разные дни.
- 406 товаров конкурентов без категории и 700 с типом `other` — кандидаты на уточнение правил классификации.
- Характеристики заполнены у 650 из 2226 товаров конкурентов; полноценно — только CrystalSound.
- Wordstat не подключён: абсолютных объёмов спроса и сезонности нет; Google Trends — относительный индекс.
- Радио Гид (radio-guide.ru) — цены по запросу; Ozon/Маркет — только ручной импорт.
- Сканирование сервисных профилей B выполнялось старым кодом; часть (58–60) упала на блокировке базы.

**Открытые задачи (в порядке договорённостей с заказчиком)**
1. Запустить `specs_extract.enrich_competitor` по всем конкурентам A и дать сводку заполненности характеристик по каждому.
2. Пересканировать сервисные профили A и B по уточнённым правилам и доменному фильтру.
3. Итоговая сводка «сайт vs радар» по товарам каждого A‑конкурента, затем та же процедура для B; затем ревизия матрицы конкурентов.
4. Доступ коллегам: проблема VPN у заказчика (отключить VPN или перенести на VPS).
5. Постоянно: +1 к версии на каждое сообщение, запись в журнал, строка «Версия сейчас» в конце ответа.

**Идеи для ветки «Товарные матрицы»** (не согласованы, для обсуждения)
- Сводная матрица «модель M22 × ближайшие аналоги конкурентов» с характеристиками и ценой за место — как отдельный экран/экспорт для закупок и прайсинга.
- Дозаполнение категории и типа для 406/700 «неопределённых» позиций (правила + ручная разметка в интерфейсе).
- Извлечение характеристик по всем A и B, затем колонки «лучше/хуже M22» прямо в матрице конкурентов.
- Единая единица сравнения для наушников (за штуку) и комплектов (за место) с проверкой пропусков вместимости.
- Wordstat‑импорт для привязки спроса к строкам матрицы.
