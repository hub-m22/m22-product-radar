# M22 Product Radar

Система рыночной разведки для M22 / RadioSync: собирает реальные данные о товарах M22 (m22.ru, radiosync.ru), конкурентах, маркетплейсах, тендерах и поисковом спросе, сопоставляет их с товарной матрицей M22 и выдаёт **сигналы**, **рекомендуемые действия**, **карточки продуктовых гипотез** и **еженедельный управленческий отчёт**.

Контур первой версии: экскурсионная деятельность и связанные B2B-решения (радиогиды, аудиогиды, синхронный перевод, наушники, микрофоны, зарядные кейсы, готовые комплекты, аренда, заменители).

## Быстрый старт (Windows / Linux / macOS)

Требуется Python 3.11+ (проверено на 3.12).

```bash
cd m22-product-radar
python -m pip install -r requirements.txt
copy .env.example .env          # Linux/macOS: cp .env.example .env
python -m radar init            # база + миграции + справочники
python -m radar collect all     # первый сбор: M22, RadioSync, конкуренты, подсказки, Google Trends (~15 мин)
python -m radar analyze         # сопоставление, сигналы, рекомендации, гипотезы
python -m radar report          # еженедельный отчёт
python -m radar serve           # веб-интерфейс: http://127.0.0.1:8022
```

На Windows задайте `set PYTHONUTF8=1` (или используйте `scripts\run.bat`), чтобы русские строки корректно выводились в консоль.

Полный цикл одной командой: `python -m radar pipeline`.

База с результатами первого реального сбора (04.09.2026) лежит в `data/radar.sqlite3`; сырые HTML-страницы — в `data/raw/<источник>/<дата>/`.

## Что внутри

| Слой | Модуль | Назначение |
|---|---|---|
| Конфигурация | `radar/config.py`, `.env` | все параметры и секреты — через переменные окружения |
| База | `radar/db.py`, `radar/migrations/*.sql` | SQLite (WAL), миграции по порядку, резервные копии |
| HTTP | `radar/http.py` | robots.txt, задержка ≥2 с на домен, повторы при 429/5xx, сохранение сырых страниц |
| Сборщики | `radar/collectors/` | `m22.py`, `radiosync.py`, `competitor_generic.py` (любая страница по URL), `wildberries.py`, `zakupki.py`, `trends.py`, `yandex_suggest.py` |
| Нормализация | `radar/normalize.py` | цены, ключ модели, категория, тип (система/приёмник/…), вместимость |
| Сопоставление | `radar/matching.py` | точная модель / прямой аналог / функциональный / комплект / аксессуар / заменитель / смежный / новая категория; уверенность; ручная проверка |
| Сигналы | `radar/signals.py` | 15 типов сигналов с порогами, защитой от повторов (`dedupe_key`), фактами/выводами/гипотезами |
| Рекомендации | `radar/recommendations.py` | конкретные действия с основанием, эффектом, уверенностью, ответственным и сроком |
| Product Discovery | `radar/discovery.py` | карточки гипотез (без автоскоринга) |
| Отчёты | `radar/reports.py` | еженедельный отчёт; экспорт PDF / XLSX / CSV / JSON |
| Планировщик | `radar/scheduler.py` | APScheduler в процессе веб-приложения; повтор после ошибки через 2 ч |
| Импорт | `radar/importers.py` | конкуренты, семантика, Wordstat CSV/XLSX, Google Trends CSV, цены вручную |
| Веб | `radar/web/` | FastAPI + Jinja2, русский интерфейс, без внешних CDN |
| Тесты | `tests/` | pytest, критическая логика на отдельной тестовой базе |

## Разделы интерфейса

Главная · Рекомендуемые действия · Категории · Сигналы · Конкуренты (реестр с категориями A/B/C, ролью и сервисным профилем; сравнительная таблица «признаки × продавцы» на `/competitors/compare`; страницы мониторинга; сопоставления) · Матрица конкурентов · Матрица M22 · Поисковый спрос · Новые возможности (гипотезы, тендеры, маркетплейсы) · Источники (статусы, журнал ошибок, планировщик, запуск сбора) · Отчёты · Настройки.

Фильтры: период, категория, товар, конкурент, тип сигнала, важность, уверенность, статус, текст. Действия: принять/отклонить рекомендацию, отправить сигнал на исследование (создаёт карточку гипотезы), комментарии, ответственный, статусы, добавление конкурента и страницы мониторинга без кода, добавление запроса, импорт файлов, экспорт CSV/XLSX, резервная копия базы.

### Сравнительная таблица конкурентов

`/competitors/compare` — признаки × продавцы, M22 первой колонкой. Признаки (гарантия, сервисный центр, подменный фонд, аренда, бесплатная доставка, бесплатный тест-драйв, монтаж, техсопровождение мероприятий, собственный склад, собственное производство, брендирование, обучение, 44-ФЗ/223-ФЗ, лизинг/рассрочка, шоурум, доставка по России, поддержка 24/7, лет на рынке, число клиентов, многоязычные решения) извлекаются со страниц сайтов регулярными выражениями; у каждой ячейки при наведении — фрагмент текста и ссылка на страницу-источник. Зелёная ячейка — конкурент заявляет то, чего нет у M22. «Нет данных» означает, что на проверенных страницах признак не найден, а не что его нет. Эталон M22 правится в «Настройках» → «Сервисный профиль M22». Границы колонок во всех таблицах можно перетаскивать.

### Юрлица и финансы конкурентов (Rusprofile)

У Rusprofile нет API, а его robots.txt запрещает роботам поиск и разделы «Финансы»/«Госзакупки», поэтому радар их **не** собирает автоматически. Данные заносятся в карточку конкурента (блок «Юрлицо и финансы»): ИНН, юрлицо, статус, ОКВЭД, дата регистрации, сотрудники, выручка за год и динамика, госзакупки (число и сумма, крупнейшие заказчики), ссылка на источник и уверенность сопоставления сайта с юрлицом (подтверждено ИНН на сайте / высокая / средняя / низкая). Выручка и госзакупки показываются в реестре, в сравнительной таблице и на вкладке «Показатели» раздела «Конкуренты» (`/competitors/dashboard`): KPI, диаграммы выручки и госзакупок по юрлицам (сайты одной группы объединены по ИНН), сводная таблица с налогами, арбитражем, исполнительными производствами, финансовым состоянием и товарными знаками. Индивидуальные предприниматели бухотчётность не сдают — для них выручки нет, только госзакупки.

## Добавление источника без переделки системы

1. **Страница конкурента**: раздел «Конкуренты» → карточка конкурента → «Добавить страницу мониторинга» (URL, тип: товар/каталог/аренда). Парсер `auto` распознаёт JSON-LD, microdata, OpenGraph, Tilda, WooCommerce и эвристику «цена рядом с названием». Для нестандартной вёрстки укажите CSS-селекторы в JSON: `{"items": ".product", "name": ".title", "price": ".price", "link": "a"}`.
2. **Новый программный сборщик**: модуль в `radar/collectors/` с функцией `run(conn) -> dict`, использующий `http.fetch` и `upsert_competitor_product`; зарегистрируйте описание в `radar/seed.py` (`SOURCE_DESCRIPTIONS`) и, при необходимости, задачу в `radar/scheduler.py`.
3. **Ручной импорт** (CSV/XLSX) — для площадок, закрытых для автоматического сбора.

## Источники: что подключено, что нет

| Источник | Статус | Как подключить |
|---|---|---|
| m22.ru, radiosync.ru | подключены (sitemap + JSON-LD / schema.org) | — |
| Сайты конкурентов (41 компания, 96 страниц) | подключены; JS-магазины и антибот — не собираются | добавить страницу в «Конкуренты» |
| Wildberries (публичный JSON поиска) | подключён (1 запрос / 20 с) | — |
| ЕИС zakupki.gov.ru (расширенный поиск) | подключён (Crawl-delay 60 с; сертификат российского УЦ — соединение без проверки, только чтение) | — |
| Google Trends (pytrends) | подключён; относительный индекс, лимит 429 — пауза 70 с между группами | — |
| Яндекс Подсказки | подключён (формулировки без объёмов) | — |
| **Яндекс Wordstat** | требует подключения | официальный API работает через Yandex Cloud Search API (сервисный аккаунт, роль `search-api.webSearch.user`, ~20 ₽ за запрос); либо выгрузка CSV/XLSX из wordstat.yandex.ru → «Поисковый спрос» → импорт (колонки `query; impressions; period`) |
| Ozon, Яндекс Маркет | заблокированы для автоматики (антибот) | ручной импорт цен или Seller/Partner API для собственного магазина |
| Поисковая выдача Яндекс/Google | заблокирована (капча) | Yandex Search API (платно, ключ в .env) или Google CSE |
| Alibaba, 1688 | заблокированы (капча, авторизация) | ручной импорт CSV |
| Made-in-China, сайты производителей (Retekess, OKAYO, MIPRO) | доступны | добавить страницы каталога в мониторинг |
| Таможенные данные ФТС | только агрегаты; детализация — платные провайдеры | подписка (ВЭД-Стат, ImportGenius) → импорт CSV |

Все статусы, ограничения и инструкции видны в разделе «Источники». Секреты (`YANDEX_WORDSTAT_TOKEN`, `ANTHROPIC_API_KEY`) читаются только из `.env` и никогда не показываются в интерфейсе. AI в текущей версии не используется: все сигналы построены на прямом сравнении данных.

## Регулярное обновление

Планировщик запускается вместе с `python -m radar serve` (`RADAR_SCHEDULE_ENABLED=1`): M22/RadioSync ежедневно в 05:00, конкуренты ежедневно в 06:00, спрос по понедельникам в 07:30, отчёт и резервная копия по понедельникам в 08:30 (часы настраиваются в `.env`). Каждая задача при ошибке повторяется через 2 часа (до 2 раз); сбои пишутся в `error_log` и показываются на главной и в «Источниках». Запуск вручную — кнопки в разделе «Источники» или CLI.

Для запуска как службы Windows используйте `scripts/run.bat` в Планировщике заданий Windows или NSSM; для Linux — `scripts/m22-radar.service` (systemd).

## Развёртывание

1. Скопируйте папку проекта на сервер, установите Python 3.11+, выполните `pip install -r requirements.txt`.
2. Создайте `.env` (см. `.env.example`); при доступе извне поставьте `RADAR_HOST=0.0.0.0` и задайте `RADAR_PASSWORD` (вход по общему паролю, cookie-сессия на `RADAR_SESSION_DAYS` дней, подпись `RADAR_SECRET`); для интернета дополнительно HTTPS через nginx (см. docs/DEPLOY.md). Порт в брандмауэре Windows открывает `scripts/open_firewall.bat`.
3. `python -m radar init && python -m radar collect all && python -m radar analyze`.
4. `python -m radar serve` под supervisor/systemd. Резервные копии: `python -m radar backup` (папка `data/backups`) — также создаются автоматически при еженедельном отчёте.

## Тесты

```bash
python -m pytest -q
```

Проверяются: разбор цен и моделей, классификация, парсеры m22.ru/radiosync.ru (на сохранённых страницах), универсальный парсер, защита от дублей, история цен, сопоставление, ценовые сигналы (в т.ч. порог ≥3 сопоставимых), расхождения сайтов, изменение цены конкурента, сигнал спроса, идемпотентность миграций. Тестовые данные не смешиваются с рабочей базой.

## Ограничения данных первой версии

- Все цены конкурентов сняты **один раз** (04.09.2026): изменения цен, появление/исчезновение товаров станут видны после второго ежедневного сбора.
- Google Trends даёт относительный индекс, а не объёмы; часть запросов близка к нулю. Абсолютные объёмы и сезонность по Яндексу появятся после подключения Wordstat.
- Сопоставления с уверенностью < 70% помечены «на ручную проверку» (раздел «Конкуренты» → «Сопоставления»).
- Подробности — `docs/FIRST_RUN_REPORT.md` и раздел «Отчёты».
